# Why are we here?

I. Introduction

    In the popular imagination, a designer is someone who comes up with ideas, produces a plan, and then hands it over to technicians to make real. The job, in this view, ends at the mock-up: thinking is ours, building is theirs. If that were true, a designer would have little reason to sit among developers, to open a code editor, or to care how a screen is actually constructed. So why are we here? Why should we, as designers, learn to code? This essay argues that coding is not a detour from design but a way of practicing it more fully. I will discuss the question from three angles: learning to code helps us communicate with developers so that designs can be implemented as intended; it helps us judge what is feasible, so that our proposals remain reasonable; and it enables us to build simple prototypes quickly, so that we can test our ideas before they go into production.
